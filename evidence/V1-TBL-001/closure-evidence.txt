## Schema notes (source: PDF:III.5 verbatim + repo decisions)
- zones: zone_id PK, code UNIQUE NOT NULL, name NOT NULL, sort_order DEFAULT 0,
  active DEFAULT true. No timestamps, no store_id (PDF has none).
- tables: table_id PK, zone_id FK nullable -> table_mgmt.zones,
  table_number TEXT NOT NULL, capacity INT DEFAULT 0, active BOOLEAN DEFAULT
  true, current_status TEXT CHECK (Available|Occupied|Reserved|Cleaning|
  OutOfService), current_order_id/current_bill_id UUID nullable (cache
  pointers, FK deferred to ORD-001/BIL-001 per C50), row_version BIGINT
  DEFAULT 1, UNIQUE NULLS NOT DISTINCT (zone_id, table_number) per
  V0-DAT-003. No created_at/updated_at (PDF defines none for tables).
- Zone/table number uniqueness is store-less; PDF defines no store_id column
  (same as catalog 006). V0-DAT-005 "isolated by store_id" rule therefore
  does not apply to this schema; noted for GATE-V1-EXIT review.
