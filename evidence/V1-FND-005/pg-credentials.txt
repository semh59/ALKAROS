V1-FND-005 PostgreSQL test credentials procedure (2026-07-31)
=============================================================

Context
-------
Host migration tests need PostgreSQL credentials on localhost:5432. The
postgres superuser password is unknown to the user; previous sessions used a
temporary pg_hba trust procedure (see pg-hba-restore.txt). This session
replaces that procedure with a dedicated, least-privilege test role and
persistent environment variables, so tests now run with normal scram-sha-256
authentication and no pg_hba modification.

Procedure (idempotent, one-time)
--------------------------------
1. Backup pg_hba.conf:
   Copy-Item C:\PostgreSQL\18\data\pg_hba.conf $env:TEMP\...\pg_hba_fnd005_fix.bak
   hash match: True

2. Switch local host lines to trust (scram-sha-256 -> trust on
   host all all 127.0.0.1/32 and ::1/128 only):
   PS> & "C:\PostgreSQL\18\bin\pg_ctl.exe" reload -D "C:\PostgreSQL\18\data"
   exit: 0

3. Create dedicated role (skipped if it already exists):
   psql -h 127.0.0.1 -U postgres -d postgres
   CREATE ROLE alkaros_test LOGIN PASSWORD '<generated 32-char>' CREATEDB;
   output: CREATE ROLE
   The role password is stored only in the user-level environment variable
   ALKAROS_TEST_PG_PASSWORD; it is never written to the repository.

4. Restore pg_hba.conf and reload:
   restore hash match: True
   local auth lines back to scram-sha-256

5. Verify scram password authentication (no trust active):
   psql -h 127.0.0.1 -U alkaros_test -d postgres
   SELECT current_user, rolcreatedb FROM pg_roles WHERE rolname=current_user;
   output: alkaros_test|t     exit: 0

6. Persist user-level environment variables:
   ALKAROS_TEST_PG_USER = alkaros_test
   ALKAROS_TEST_PG_PASSWORD = <generated 32-char>

Result
------
- dotnet test tests/Host/MigrationComposition (46/46) with scram auth, no
  trust modification: EXIT 0
- Full solution test 75/75 (Architecture 4 + Host 46 + Transactions 25): EXIT 0
- No pg_hba.conf change is needed for future local test runs.

Test surface fix required by the credential switch
--------------------------------------------------
ProgramMainProducesTheDocumentedExitCodes passed the db-url to Program.Main
without a password; this only worked because trust accepted password-less
connections. The test now appends --db-password when the fixture carries a
password (null password keeps the previous behavior). This is a V1-FND-004
test-surface change, required by the approved credential strategy fix.

CI note
-------

pointing at the CI PostgreSQL instance.
