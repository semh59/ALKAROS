## Scope executed
- `src/Modules/Billing/BillFoundation/BillItem.cs`:
  - Added an optional constructor parameter `decimal? trueGrossAmount = null`.
    When present it replaces `lineSubtotal` as the value `DiscountAmount`
    must equal for a Complimentary line, breaking the tautology where
    `netAmount` is passed explicitly (every real `FromOrderItem` call):
    previously `lineSubtotal = RoundCurrency(netAmount + DiscountAmount)`
    with `netAmount == 0m` reduced to `lineSubtotal == DiscountAmount`,
    comparing `DiscountAmount` to itself.
  - `FromOrderItem`'s Complimentary branch now passes
    `trueGrossAmount: orderItem.LineSubtotalValue` — an independent value
    (quantity * unit price plus modifiers, already a public property on
    `OrderItem`, no change needed there) computed without any reference to
    `NetAmount`/`DiscountAmount`. If a caller's `NetAmount`/`DiscountAmount`
    bookkeeping ever drifts from that true gross (e.g. a modifier total
    forgotten on reload), the constructor now throws instead of silently
    accepting it.
  - Backward compatible: `trueGrossAmount` defaults to `null`, in which
    case behavior is identical to before (falls back to `lineSubtotal`) —
    the existing `ComplimentaryLineConstructedDirectlyRejectsAPartialDiscount`
    test (direct constructor call, no `netAmount`, no `trueGrossAmount`)
    is untouched and still passes.
- `tests/Modules/Billing/BillFoundation/BillDomainTests.cs`: 2 new tests
  (`ComplimentaryFromOrderItemRejectsADiscountThatDoesNotMatchTheTrueGross`,
  `MixedSaleAndComplimentaryBillTotalsPayableExcludesTheCompLine`); no
  existing test changed.
