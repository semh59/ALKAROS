## Scope executed
`src/Modules/Billing/PaymentClosure/**`: a deterministic, side-effect-free
projection of a Bill's payment-closure state (PDF:I.26-I.29/II.2.6/
II.3.4-II.3.5/II.5.3/III.8):
- BillPaymentClosureProjection.cs: the record (BillId, CurrencyCode,
  PayableAmount, AllocatedTotal, PaidTotal, ChangeTotal, PaymentSatisfied,
  Blockers) and BillClosureBlocker enum (NotFullyAllocated,
  HasPendingPayment, HasUnknownPayment).
- BillPaymentClosureCalculator.cs: pure function `Compute(bill, payments,
  allocations)` — no database, unit-testable in isolation (same separation
  PaymentAllocationFactory already established). Only Status == Approved
  payments ever contribute (Pending/Unknown/Declined/Cancelled never
  produce PaymentSatisfied, this task's own Acceptance evidence);
  allocations are cross-referenced against that same approved-payment set
  rather than trusted at face value ("authoritative Payment kayıtlarından").
  PaymentSatisfied = AllocatedTotal >= PayableAmount (>0).
- BillPaymentClosureProjector.cs / IBillPaymentClosureProjector.cs: loads
  the real Bill + its Payments + its PaymentAllocations and calls the pure
  calculator — a genuine "rebuild" every call (Acceptance evidence:
  "Rebuild projection deterministiktir"), never a mutable stored flag that
  could drift from the underlying ledger.
- PaymentClosureExceptions.cs: PaymentClosureBillNotFoundException.
- BillPaymentClosureModule.cs: its own IModule (not yet added to
  ModuleRegistry.DefaultCatalog, same reasoning as V13-CSH-003 — the full
  V1.3 HTTP composition is a later task's job, likely V13-FSC-002).

## A real circular-dependency conflict found and resolved
Payments already references Billing (ALKAROS.Payments.csproj ->
ALKAROS.Billing.csproj), but this task's own code (physically under
src/Modules/Billing/PaymentClosure/, per its Owned surface) needs Payment/
PaymentAllocation types from the Payments assembly — a straight
Billing -> Payments reference would have cycled. Resolved by giving
PaymentClosure/** its own separate project
(ALKAROS.Billing.PaymentClosure.csproj, referencing BOTH
ALKAROS.Billing.csproj and ALKAROS.Payments.csproj — no cycle, since
Billing itself never references back), with a `<Compile Remove>` added to
ALKAROS.Billing.csproj so its own default file glob does not also compile
the same sources into that assembly.
