Changes:
- Messaging: OutboxRetryProfile(EventType, MaxAttempts, BaseDelay, MaxDelay). OutboxStore takes profiles; a
  message of a profiled event type uses its own attempt budget and a capped wait (LEAST(cap, base x 2^n));
  every other event type keeps the default (3 attempts, store base delay, no cap). Duplicate profiles for one
  event type are refused. The host builds its store in one place (OutboxComposition.CreateStore), also used
  by the kitchen registration, so whichever registration wins the profiles apply.
- OnlineOrderingModule registers the provider profile (12 attempts, 30 s x 2^n, at most 30 min: ~3 h before
  dead) for Yemeksepeti status updates and catalog publications. A dead update still surfaces as the existing
  LocallyAcceptedProviderUnknown case.
- YemeksepetiPartnerHttpClient: a 401 drops the cached token if it is still the one the call used; other
  errors keep it.
- CancelLocallyAsync: the order's kitchen tickets are locked (FOR UPDATE, V1-RMD-313 overload) in the
  cancellation transaction before the stock decision and saved in it. No FOR SHARE in
  PostgresKitchenItemStateProvider (every kitchen write updates its ticket row first, so the ticket lock gives
  the same guarantee without crossing the module boundary).
- HandOverAsync walks the online order to Completed (platform settles payment); a later provider
  cancellation stays Diverged evidence. No backfill migration: there is no live online data (V0-YSP-001).
- Normalizer carries each product's catalog price (CatalogPrice); PriceDifferences lists lines whose provider
  price differs; intake records pricesMatch / priceDifferenceAmount / priceDifferences; new
  ProviderPriceMismatch source pair (manual resolution, amount = sum |provider - catalog| x quantity).
- Online operations endpoint errors: handover without a known delivery kind -> 409 HANDOVER_NOT_SUPPORTED;
  stock configuration / insufficient stock -> 409 STOCK_NOT_AVAILABLE (Turkish messages).
