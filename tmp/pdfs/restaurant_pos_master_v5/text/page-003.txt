I.0 Executive Decision
Bu belge, tek şubeli restoran POS ürününün geliştirme yol haritasını
sürümlere böler.
Amaç yeni özellikleri sonsuza kadar eklemek değildir. Amaç, Domain
Specification'a geçmeden önce roadmap seviyesindeki bütün kritik
domain kararlarını kapatmaktır.
Final hedef:
C# / .NET + PostgreSQL tabanlı, local-first çalışan, English codebase
kullanan, Turkish UI sunan, Hugin T300 ile fiscal/payment
entegrasyonu bulunan, QNB eSolutions ile e-belge süreçlerini
yöneten, Yemeksepeti ve QR siparişlerini aynı Order domain'inde
birleştiren, günlük menü + reçete + üretim + porsiyon stoğu + cari +
meal card + mutfak + yazıcı + backup + audit + reconciliation
özelliklerine sahip, production-grade Modular Monolith.
Microservice'e geçilmeyecek.
Sürüm numaraları ürünün zorunlu production release'leri değil; geliştirme
kilometre taşlarıdır. V2.0 bitene kadar hiçbir ara sürüm gerçek
kullanıcı/gerçek para ile temas etmez.
I.1 Kesinleşmiş Sabit Kararlar
I.1.1 Mimari
Architecture: Modular Monolith
Deployment: Single application/backend deployment
Database: Single PostgreSQL instance
Domain boundaries: Explicit modules
Internal communication: direct application calls where appropriate +
domain events/integration events
External integrations: Adapter/Anti-Corruption Layer
Distributed microservices: YOK
Service-per-domain deployment: YOK
Kafka/RabbitMQ gibi zorunlu distributed broker: YOK
