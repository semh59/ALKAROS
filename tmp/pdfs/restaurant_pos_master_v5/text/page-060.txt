III.8.2 payment_allocations — CORRECTED (Corrections v5 §1,
closes audit finding B2)
Prior defect:unique(payment_id, bill_id, bill_allocation_id) did not
protect the
common case where bill_allocation_id IS NULL, because PostgreSQL
treats
every NULL as distinct in a standard unique constraint — duplicate direct-
to-Bill allocations from retried/duplicated provider callbacks could pass
silently. This is now fixed with a required idempotency_key and two
partial unique indexes.
create table payments.payment_allocations (
    payment_allocation_id   uuid primary key,
    payment_id              uuid not null references 
payments.payments,
    bill_id                 uuid not null references 
billing.bills,
    bill_allocation_id      uuid null references 
billing.bill_allocations,
    allocated_amount        numeric(18,2) not null check 
(allocated_amount > 0),
    idempotency_key         text not null,
    created_at              timestamptz not null
);
