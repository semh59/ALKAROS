III.14.5 portion_reservations
inventory.portion_reservations: portion_reservation_id PK,
daily_menu_item_id FK not null, order_id FK not null, order_item_id FK
nullable, quantity not null, status not null, reserved_at not null, released_at
null, consumed_at null, waste_at null, reason null.
Canonical status (→ II.5.6): Reserved, Released, Consumed, Waste.
Concurrency contract:portion_reservations is append/update history
for individual reservations; it does not own the stock race. The authoritative
concurrency token is inventory.stock_balances.row_version (III.14.3).
Reservation creation and stock decrement/reservation must occur in one
PostgreSQL transaction using row locking/optimistic concurrency on the
stock balance. Therefore a row_version on portion_reservations is
intentionally not required for the last-portion race — this asymmetry is
deliberate, not an oversight.
Constraint: one reservation record must not consume more than the
available portion pool allows.
