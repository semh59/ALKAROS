C9 — recipe_ingredients.waste_factor order-of-operations
vs. unit_conversions not specified
Finding:recipe.recipe_ingredients (III.12.3) has both quantity +
unit_code and a separate waste_factor numeric(18,4) default 0.
recipe.unit_conversions (III.12.4) separately converts between units.
Neither Part II nor Part III states the order of operations when a
production batch consumes raw material: is waste_factor applied before
or
after unit conversion to the stock item's native unit? (E.g., if a recipe
calls for 200 g of an ingredient with a 5% waste factor, and the
stock_items row is tracked in kg, does the system compute
200g × 1.05 = 210g, then convert to 0.21 kg; or convert first to
0.2 kg, then apply waste factor to get 0.21 kg? For a linear
percentage factor these are mathematically equivalent — but if
waste_factor were ever changed to a non-linear/tiered model in the
future, the order would matter, and it costs nothing to state it now.)
Fix: Add one sentence to III.12.3: "Effective consumption quantity =
recipe_ingredients.quantity × (1 + waste_factor), computed in the
recipe's native unit_code, then converted to the stock item's tracked
unit via unit_conversions as the final step." Low severity, but exactly
the kind of ambiguity that becomes expensive once
production_consumptions
rows (III.13.3) have already been written using an undocumented, possibly
inconsistent order.
