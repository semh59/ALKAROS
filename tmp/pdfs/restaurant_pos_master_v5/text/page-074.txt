Prior defect:invoice_items.source_transaction_id (an untyped,
undiscriminated
polymorphic reference) duplicated the purpose of
invoicing.invoice_sources
(III.20.3), which already implements a proper typed polymorphic pattern.
Having both with no stated authority order risked two divergent
implementations. source_transaction_id is removed.
invoicing.invoice_items: invoice_item_id PK, invoice_id FK not null,
description not null, quantity not null, unit_price not null, tax_rate not null,
net_amount not null, gross_amount not null.
invoicing.invoice_sources (III.20.3, unchanged) remains the single
authoritative mechanism linking an invoice to the account_transactions
(or other) rows it was generated from. Each invoice_item is associated
with its origin indirectly, through the invoice-level invoice_sources set —
sufficient because periodic invoicing operates on whole billing periods, not
per-line traceability finer than the source transaction set already captures.
If line-level traceability is later required, add an invoice_sources_item_id
FK column on invoice_items referencing invoice_sources, rather than
reviving the removed ad-hoc field.
III.20.3 invoice_sources
invoicing.invoice_sources: invoice_source_id PK, invoice_id FK not null,
source_type not null, source_reference_id not null. Constraint:
unique(invoice_id, source_type, source_reference_id). Single authoritative
mechanism — see III.20.2 note.
